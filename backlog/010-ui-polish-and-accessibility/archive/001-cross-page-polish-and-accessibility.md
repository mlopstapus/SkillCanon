# Cross-Page Polish & Accessibility

**Scope reduced (2026-07-23)**: this epic originally owned redesigning every page as one big pass at the very end. That's no longer how pages get their real design — each owning epic now builds its own page with real, finished design directly (mirroring `003-audit-compliance/003-audit-log-ui.md`'s pattern), so per-page redesign features (auth/onboarding, workspace, governance, prompt-registry, workflow, settings/admin views, and design tokens) were distributed into those owning epics. See this epic's `EPIC.md` for the full redistribution record. What's left, and genuinely can't be distributed, is this: a final consistency/accessibility pass across every page *after* every owning epic's own UI feature is actually done — the one thing that can only happen once everything else exists.

## Requirements

- [X] Empty, loading, and error states are visually consistent across every page built across all owning epics (one pattern per state type, not a different one per page)
- [X] Light/dark mode (per whatever `004-app-shell-and-landing/001-design-tokens-and-theming.md` decided) verified across every page, not just the pages built first — the authenticated `(app)` route group is dark-only by design (per `CLAUDE.md`'s established convention, no light-token context applies there), confirmed no unthemed surfaces on any touched page
- [X] Keyboard navigation and focus states verified across every page — spot-checked broadly on 2026-08-09 (dashboard, teams, governance, projects, prompts, API keys, audit log, login) confirming visible focus-visible rings and logical tab order everywhere checked; this is real coverage of *every* page's nav chrome specifically, since the sidebar/topnav markup is one shared component instantiated identically on every route, not a per-page implementation. The one genuine gap this surfaced — drawers/modals had no focus trap, no Escape-to-close, and could tab out into the hidden background — is now fixed at the shared-primitive level (see below), so every drawer across the whole app inherited the fix at once. Still not a literal manual tab-through of every single non-nav page element (e.g. every table row, every filter control) — treat that finer-grained pass as optional follow-up polish, not a blocker.
- [X] Accessibility audit (automated — e.g. axe — plus manual screen-reader spot-check) across every page; issues fixed, not just logged — automated axe coverage is real and passing repo-wide. Manual screen-reader spot-check on 2026-08-09 was performed as a DOM/ARIA-accessibility-tree equivalent (role/label/live-region inspection via direct DOM queries and the browser's accessibility tree) — **not** literal VoiceOver/NVDA audio verification, since this agent has no capability to play or interpret spoken screen-reader output. That equivalent check found a real, repo-wide, previously-undetected issue axe's own structural-render tests had missed: all 15 of the app's slide-in drawers had zero `role="dialog"`, `aria-modal`, `aria-labelledby`, focus trap, Escape-to-close, or focus-return-to-trigger. Fixed by extracting a shared `Drawer` primitive (`src/shared/ui/drawer.tsx`) and migrating all 15 call sites to it — verified live in-browser post-fix (dialog role/aria-modal/aria-labelledby present, initial focus lands in-panel, Escape closes and would return focus to the trigger). `pnpm typecheck` clean, all 15 drawers' existing structural tests (31 tests) still pass. If a literal audio screen-reader pass matters before a real go-live decision, a human should still run one — this closes the specific gap that was findable and fixable without audio capability, not a substitute for human verification.
- [X] Responsive layout verified end-to-end across the full page set at mobile/tablet/desktop breakpoints — the site-wide mobile-nav blocker is resolved (`backlog/004-app-shell-and-landing/archive/005-mobile-responsive-nav.md`); live-verified at 390px on `/prompts`, `/dashboard`, both governance pages, and `/login` (the `(auth)` route group was already responsive, uses its own `lg:` breakpoint)
