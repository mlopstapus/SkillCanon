# Quickstart: Audit Log UI

Validates the feature end-to-end against a real dev database — no dedicated seed script exists in this repo, so events are generated by exercising the app's own existing flows.

## Prerequisites

- `pnpm install` (once)
- Postgres reachable per `docker-compose.yaml` defaults (or a remapped port per `CLAUDE.md` if another project already occupies 5432/3000 locally)
- `pnpm db:migrate` applied

## Setup

```bash
pnpm exec next dev -p 3001   # or `pnpm dev`; see CLAUDE.md for the -p flag gotcha
```

1. Register the first-run admin at `/register` (this becomes an org admin — the only role that can reach `/settings/audit-log`).
2. Generate a mix of real audit events by using the app normally, e.g.:
   - Create a team, then edit it, then reparent it (`team.created`/`team.updated`/`team.reparented`)
   - Issue an API key, then revoke it (`api_key.created`/`api_key.revoked`)
   - Invite a member by email (`invitation.created`)
   - Create a policy or objective and edit it (`policy.created`/`policy.updated`)
   - Log out and back in (`user.logout`/`user.login`)
   - Attempt (and fail) a login with a wrong password (`user.login_failed`)

## Validate: browsing and filtering (User Story 1)

1. Sign in as the admin, open **Settings → Audit log**.
2. Confirm events render newest-first, each with time (absolute + relative), a color-coded action badge, resolved resource name, actor, and transport badge.
3. Type into the search box — confirm the list narrows to matches on action/resource/actor.
4. Select a Resource, an Actor, a Transport, and a date-range preset together — confirm the list narrows to the intersection of all four.
5. Select "Clear filters" — confirm every filter resets and the button itself disappears once no filter is active.
6. Sign out, sign in as a non-admin member (invite one, accept the invite in an incognito/second session) — confirm `/settings/audit-log` denies access (redirect), both by navigating directly and by re-checking that no data was fetched.

## Validate: event detail (User Story 2)

1. Click a mutation event (e.g. the `team.updated` row) — confirm the drawer shows a field-by-field before/after diff, the resolved resource name as the header title, actor/source/resource/timestamp in the meta grid, and the event's own id in the footer.
2. Click a `user.login`/`user.logout` row — confirm the "no state change recorded" explanatory copy appears instead of an empty diff.
3. Click the `api_key.created` row — confirm the diff does **not** render the real `key_hash` value anywhere, even though the underlying event's `after` payload contains a redacted placeholder for it (per `record()`'s existing redaction).
4. Dismiss the drawer — confirm the underlying filtered list and page position are unchanged.

## Validate: empty/no-match states (User Story 3)

1. On a brand-new org with zero audit events (register a second, fresh org), open the Audit Log page — confirm the "no events yet" message with no "Clear filters" action.
2. On the seeded org, apply a filter combination that matches nothing (e.g. an actor + resource combination that never co-occurred) — confirm the distinct "no events match these filters" message and a working "Clear filters" action.

## Validate: pagination and retention label

1. Generate enough events to exceed one page (or lower `DEFAULT_AUDIT_PAGE_SIZE` locally for testing) — confirm paging through the trail loads correctly-scoped results.
2. Confirm the footer's retention label reflects the org's actual resolved value from `resolveAuditEntitlements()` (currently the hardcoded 7-day Free default pending the Billing epic) — never a hardcoded "90 days (Free)" string like the mockup's own placeholder sample data.

## Validate: export hidden (User Story 4)

1. Confirm no Export control renders anywhere on the page today (Billing & Entitlements doesn't exist yet) — this is the correct current-state behavior per FR-014, not a bug.
